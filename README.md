# Dream Architect · 梦境建筑师

基于 Portal 的非欧几何空间探索引擎 + 可游玩的第一人称游戏。Three.js 0.186 + TypeScript + 自写 GLSL 着色器。

**▶ 在线体验：https://123huangcan250.github.io/dream-architect/**（桌面浏览器 + 鼠标键盘，点击画面锁定视角）

```bash
npm install
npm run dev        # http://localhost:5199
npm test           # 133 个自动化测试（Vitest，Node 环境，无需 GPU）
npm run build      # 类型检查 + 生产构建到 dist/
```

## 游戏内容

| 模式 | 内容 |
| --- | --- |
| **开始梦境**（剧情） | 《梦之宅》：庭院里 2.4 m 的衣柜通向 36×50 m 的大厅；四个侧厅各藏一枚碎片，集齐后觉醒之门开启。 |
| 无尽回廊 | 16 m 的走廊首尾相接，向前走永远走不出去；只有**倒退着**穿过北端才会被重定向到密室。 |
| 彭罗斯阶梯 | 四段楼梯每段都在上升，一圈后却回到起点（传送门做纯 −8 m 平移）。爬两圈后楼梯尽头被重连到云端之顶。 |
| 罗盘之间 | 三扇门的去向会在你**移开视线时**洗牌；盯着金色房间走进去。 |
| 视差画廊 | 站在发光点上，散落碎片对齐成桥并变成实体；拿起小方块望向远处，它会按“近大远小”变成 2 m+ 的台阶。 |
| 镜廊 | 两扇互相链接的门面对面，形成无限递归隧道。 |
| **迷梦回廊** | 程序生成的环面迷宫（东西、南北边缘通过传送门相连）+ 死胡同虫洞；G 键用 A* 显示穿越传送门的最短路径。 |
| **悖论谜题** | 生成器随机构造房间/门拓扑（单向门、自环、拉杆切换链接），BFS 求解器只接受“可解且必须改变空间结构才能解”的题；H 键给出求解器提示。 |
| **场景编辑器** | 方块/传送门/道具放置、多选、链接、旋转、尺寸调整、检查器、规则 JSON、实时校验、撤销重做、保存槽、JSON 导入导出、从当前视角试玩。 |

操作：WASD 移动 · 鼠标环顾 · Shift 奔跑 · 空格 跳跃 · E 互动 · 左键 拿起/放下 · G 迷宫指引 · H 谜题提示 · F3 性能统计 · Esc 暂停。

## 架构

```
src/core/      纯逻辑，无 DOM / WebGL —— 全部可单测
  portalMath   传送门坐标系、穿越变换 M = To·RotY(π)·From⁻¹、穿越检测、Lengyel 斜近裁剪投影
  World        碰撞几何（空间哈希）、传送门图、门感知的碰撞/地面查询、穿门射线
  character    角色控制器：子步进、台阶、斜坡、跳跃、天花板、先穿越后解算碰撞
  renderPlan   递归视图规划（BFS + 预算）：单面剔除、近平面/裁剪面多边形裁剪、屏幕矩形嵌套、距离剔除
  topology     动态拓扑规则：立即/未被观察时重连、洗牌、计数器、区间触发、站在门中时延迟
  perspective  错觉碎片（沿视线等比缩放）、对齐判定、强制透视
  level        关卡格式、迁移、校验、保存槽
src/gen/       builder · storyLevel · maze(+torus/wormholes) · pathfinding(A*/BFS) · puzzle(生成+求解+落地)
src/render/    shaders(GLSL) · WorldView(合批) · PortalRenderer(递归执行)
src/game/      Game 主循环 · Props 交互 · Input · Audio(纯合成) · UI
src/editor/    Editor
```

### 重点问题的解决方式

- **递归渲染**：`planViews` 先在 CPU 上以广度优先建出视图树（浅层大门优先占用预算），`PortalRenderer` 再深度优先执行：子视图渲染到按深度缩放分辨率的池化 RenderTarget，门面着色器用 `gl_FragCoord / resolution` 屏幕空间采样。超出深度/预算的门用雾色填充，与指数雾自然融合。
- **门后几何泄漏**：默认用 GPU 全局裁剪平面（着色器 discard，稳健）；设置里可切换到 Lengyel 斜投影近裁剪（更快）。两者都有测试。
- **近平面穿门闪烁**：相机贴近门时，门面临时加厚为向后延伸 0.18 m 的盒子，近平面切进门里也看到的是门后画面。
- **穿越判定**：用水平位移线段与门矩形求交，只接受“正面→背面”；先穿越再解算碰撞，避免门后被隐藏的几何把身体推回；速度、朝向、累计海拔随变换一起映射；“倒退穿越”作为触发条件暴露给规则系统。
- **碰撞**：身体与门洞重叠时，丢弃门后（本侧）的几何，并把目标侧门前的几何映射回本空间参与碰撞；地面采样点若落在门后，则到目标空间取地面高度再映射回来（彭罗斯楼梯靠这个才能无缝走过）。
- **拓扑变化不穿帮**：重连只在门未被渲染（任意递归深度）且玩家不在门洞中时生效；穿越瞬间只允许“立即”模式改动当前门。
- **性能**：静态方块按 64 m 区块 × 材质合批；每个视图做视锥/裁剪面/雾距三重剔除，道具按距离剔除；子视图剪裁到门的屏幕矩形；自适应先降递归预算再降分辨率。集显（Intel UHD）上 1152×864、9 个递归视图约 13 ms/帧。

## 说明

- “AI 生成谜题”是**搜索式生成器 + BFS 求解器**（生成—验证循环，带难度与“必须改变拓扑”约束），本地离线运行，不调用大语言模型。
- 关卡保存在浏览器 `localStorage`；导出/导入为 `.dream.json`。
- 无外部美术/音频资源：材质全部为程序化 GLSL，音效为 WebAudio 合成。
